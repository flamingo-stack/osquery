Integration test for the `deb_packages` osquery table, validating that Debian package data is correctly queried and structured on systems with `dpkg` installed.

## Key Components

- **`DebPackages`** — Test fixture class inheriting from `testing::Test`, initializes the test environment via `setUpEnvironment()`.
- **`TEST_F(DebPackages, test_sanity)`** — Primary sanity check that:
  - Executes `SELECT * FROM deb_packages`
  - Validates row schema using a `ValidationMap`
  - Asserts the `dpkg` package is present in results
  - Runs container-row validation on Linux platforms

## Validated Schema Fields

| Field | Validation Rule |
|---|---|
| `name` | `NonEmptyString` |
| `version` | `NonEmptyString` |
| `source` | `NormalType` |
| `size` | `IntOrEmpty` |
| `arch` | `NonEmptyString` |
| `revision` | `NormalType` |
| `status` | `NonEmptyString` |
| `maintainer` | `NonEmptyString` |
| `section` | `NormalType` |
| `priority` | `NormalType` |
| `admindir` | `NonEmptyString` |

## Usage Example

```cpp
// Run the test directly via osquery test runner
TEST_F(DebPackages, test_sanity) {
  QueryData rows = execute_query("select * from deb_packages");

  // Skips gracefully if dpkg is not installed
  if (rows.size() > 0) {
    validate_rows(rows, row_map);
    ASSERT_EQ(all_packages.count("dpkg"), 1u);
  }
}
```

> **Note:** If the query returns empty results, the test logs a warning and skips assertions — assuming `dpkg` is not present on the system rather than failing hard.
