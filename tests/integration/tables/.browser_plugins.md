Integration test for the `browser_plugins` osquery table, validating schema correctness and macOS version-conditional data presence on Darwin systems.

## Key Components

- **`browserPlugins`** — Test fixture class inheriting from `testing::Test`, initializes the test environment via `setUpEnvironment()`.
- **`test_sanity`** — Single test case that validates the `browser_plugins` table schema and query behavior.
- **`row_map`** — `ValidationMap` defining expected column types for the table schema.

### Validated Columns

| Column | Type |
|---|---|
| `uid` | `IntType` |
| `name` | `NormalType` |
| `identifier` | `NormalType` |
| `version` | `NormalType` |
| `sdk` | `NormalType` |
| `description` | `NormalType` |
| `development_region` | `NormalType` |
| `native` | `IntType` |
| `path` | `NormalType` |
| `disabled` | `IntType` |

## Usage Example

```cpp
// Runs automatically via the osquery integration test suite.
// The test conditionally asserts data presence based on macOS version:
// - macOS < 10.15: browser_plugins table must return non-empty results
// - macOS >= 10.15: table must return empty (feature removed by Apple)

auto data = execute_query("select * from browser_plugins");
auto datauser = execute_query("select * from browser_plugins where uid = 0");
validate_rows(data, row_map);
```

> **Note:** Browser plugins (NPAPI) were removed in macOS 10.15 (Catalina). The test accounts for this by asserting an empty result set on Catalina and later, and non-empty results on earlier versions.
