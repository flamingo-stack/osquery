Integration test for the `deviceguard_status` osquery table, validating that the Windows Device Guard status query returns well-formed rows with expected fields.

## Key Components

- **`DeviceGuardStatus`** — Test fixture inheriting from `testing::Test`, initializes the osquery test environment via `setUpEnvironment()`.
- **`TEST_F(DeviceGuardStatus, test_sanity)`** — Sanity test that executes `SELECT * FROM deviceguard_status`, asserts at least one row is returned, and validates field types against a `ValidationMap`.

### Validated Fields

| Field | Constraint |
|---|---|
| `version` | `NonEmptyString` |
| `instance_identifier` | `NormalType` |
| `vbs_status` | `NonEmptyString` |
| `code_integrity_policy_enforcement_status` | `NonEmptyString` |
| `umci_policy_status` | `NonEmptyString` |
| `configured_security_services` | `NonEmptyString` |
| `running_security_services` | `NonEmptyString` |

## Usage Example

```cpp
// Run this test via the osquery integration test harness (Windows only).
// Corresponds to: specs/windows/deviceguard_status.table

TEST_F(DeviceGuardStatus, test_sanity) {
  QueryData data = execute_query("select * from deviceguard_status");

  // Expect at least one result row
  ASSERT_GE(data.size(), 1ul);

  // Validate each row matches expected schema types
  ValidationMap row_map = {
      {"vbs_status", NonEmptyString},
      {"running_security_services", NonEmptyString},
      // ...
  };
  validate_rows(data, row_map);
}
```

> **Platform:** Windows only. The corresponding table spec is located at `specs/windows/deviceguard_status.table`.
