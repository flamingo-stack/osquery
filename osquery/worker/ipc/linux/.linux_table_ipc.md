Inter-process communication layer for Linux-based osquery table workers, providing JSON-over-pipe messaging between parent and child processes using blocking `PipeChannel` connections.

## Key Components

### `LinuxTableIPC`
Extends `TableIPCBase<LinuxTableIPC>` (CRTP pattern) to manage bidirectional pipe-based IPC for table query workers.

| Method | Description |
|--------|-------------|
| `sendJSONString` / `recvJSONString` | Low-level JSON string transport over the active pipe channel |
| `processLogMessage` | Handles incoming log messages from a child process |
| `processJobMessage` | Handles incoming query job dispatch messages |
| `processQueryDataMessage` | Receives and deserializes query results into `QueryData` |
| `createChannelTicket` | Allocates a new `PipeChannelTicket` via the factory |
| `connectToChild` / `connectToParent` | Establishes the active pipe channel from either side of a fork |
| `setActiveChannelIfOpen` | Selects an existing open channel by table name |
| `closeActiveChannel` | Tears down the current pipe connection |
| `getTableNameFromPid` | Resolves a table name from a child PID |
| `isChannelOpen` / `getRemotePid` / `getTableName` | Channel state accessors |

### `LinuxTableIPCLogger`
A `Logger` adapter that forwards `log()` and `vlog()` calls through `LinuxTableIPC::sendLogMessage`, routing child-process log output back to the parent via the IPC channel.

## Usage Example

```cpp
// Parent-side setup
PipeChannelFactory factory;
TableIPCMessageHandler handler;
LinuxTableIPC ipc(factory, handler);

auto ticket = ipc.createChannelTicket();
pid_t child_pid = fork();

if (child_pid == 0) {
    // Child process
    ipc.connectToParent("my_table", ticket);
    LinuxTableIPCLogger logger(ipc);
    logger.log(1, "Child process started");
} else {
    // Parent process
    ipc.connectToChild("my_table", ticket, child_pid);

    QueryData results;
    ipc.processQueryDataMessage(json_msg, results);
}
```
