Implements a unidirectional pipe-based IPC channel for inter-process communication between osquery worker processes, wrapping POSIX pipe file descriptors with message send/receive semantics.

## Key Components

- **`PipeChannel`** — Concrete class extending `TableChannelBase<PipeChannel>` (CRTP pattern) that manages a pair of read/write pipe file descriptors for IPC communication with a remote process.

| Member | Description |
|---|---|
| `PipeChannel(table_name, read_pipe_fd, write_pipe_fd, remote_pid)` | Constructs a channel bound to existing pipe FDs and a remote PID |
| `~PipeChannel()` | Closes both pipe FDs on destruction |
| `getRemotePid()` | Returns the PID of the remote process on the other end of the channel |
| `sendStringMessageImpl()` | CRTP hook — writes a string message to the write pipe |
| `recvStringMessageImpl()` | CRTP hook — reads a string message from the read pipe |
| `blockSIGPIPE()` / `restoreSIGPIPE()` | Guards writes against broken pipe signals, saving and restoring the signal mask |

- **`PipeChannelFactory`** — Forward-declared factory (defined separately) responsible for constructing `PipeChannel` instances.

## Usage Example

```c
// Typically constructed via PipeChannelFactory, not directly.
// Illustrative usage after channel creation:

PipeChannel channel("my_table", read_fd, write_fd, child_pid);

std::string message = "query_payload";
Status send_status = channel.sendStringMessage(message);

std::string response;
Status recv_status = channel.recvStringMessage(response);

pid_t remote = channel.getRemotePid(); // child_pid
```

> **Note:** `PipeChannel` is non-default-constructible — instances must be created with valid pipe FDs and a remote PID, typically via `PipeChannelFactory`. SIGPIPE is automatically blocked during writes to prevent signal-driven crashes on broken pipes.
