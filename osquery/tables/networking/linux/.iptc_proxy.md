A C header providing a proxy abstraction layer over `libiptc` for reading `iptables` chain and rule data, enabling safe iteration over firewall chains and rules within osquery table implementations.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `iptcproxy_handle` | Opaque handle representing an active iptables connection for a given filter table |
| `iptcproxy_chain` | Describes a chain: name, policy string, and packet/byte counters |
| `iptcproxy_rule` | Describes a rule: target, optional port match data, and full IP match criteria (addresses, masks, interfaces, protocol, flags) |

### `invflags` Bitmask Constants

Used in `iptcproxy_rule.ip_data.invflags` to invert match semantics:

| Constant | Value | Meaning |
|----------|-------|---------|
| `IPTC_INV_VIA_IN` | `0x01` | Invert inbound interface |
| `IPTC_INV_VIA_OUT` | `0x02` | Invert outbound interface |
| `IPTC_INV_SRCIP` | `0x08` | Invert source IP |
| `IPTC_INV_DSTIP` | `0x10` | Invert destination IP |
| `IPTC_INV_PROTO` | `0x40` | Invert protocol |
| `IPTC_INV_MASK` | `0x7F` | All flags mask |

### Functions

- **`iptcproxy_init(filter)`** — Initialize a handle for the named table (e.g., `"filter"`, `"nat"`)
- **`iptcproxy_free(handle)`** — Release all resources associated with a handle
- **`iptcproxy_first_chain / iptcproxy_next_chain`** — Iterate over all chains in the table
- **`iptcproxy_first_rule / iptcproxy_next_rule`** — Iterate over rules within a named chain

## Usage Example

```c
const iptcproxy_handle* h = iptcproxy_init("filter");
if (!h) return;

const iptcproxy_chain* chain = iptcproxy_first_chain(h);
while (chain) {
    const iptcproxy_rule* rule = iptcproxy_first_rule(chain->chain, h);
    while (rule) {
        /* Check if source IP match is inverted */
        if (rule->ip_data.invflags & IPTC_INV_SRCIP) {
            /* handle inverted source IP */
        }
        rule = iptcproxy_next_rule(h);
    }
    chain = iptcproxy_next_chain(h);
}

iptcproxy_free(h);
```
