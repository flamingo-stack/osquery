BPF-based socket event subscriber for osquery that captures and processes Linux socket-related system events via the BPF event publisher pipeline.

## Key Components

- **`BPFSocketEventSubscriber`** — Final class extending `EventSubscriber<BPFEventPublisher>` that subscribes to BPF-sourced socket events on Linux.
- **`init()`** — Initializes the subscriber and registers it with the BPF event publisher.
- **`eventCallback()`** — Invoked per-event; receives an event context and subscription context for processing incoming socket events.
- **`generateRow()`** — Static helper that converts a single `ISystemStateTracker::Event` into an osquery `Row` for table output.
- **`generateRowList()`** — Static helper that batch-converts an `ISystemStateTracker::EventList` into a vector of `Row` objects.

## Usage Example

```c
// Subscriber is auto-registered via osquery's event framework.
// generateRow is used internally during event processing:

Row row;
bool success = BPFSocketEventSubscriber::generateRow(row, event);
if (success) {
    // row now contains socket event fields (fd, pid, family, etc.)
}

// Batch processing from an event list:
auto rows = BPFSocketEventSubscriber::generateRowList(event_list);
for (const auto& r : rows) {
    // emit or store each row
}
```

## Notes

- Linux-only; depends on `BPFEventPublisher` and `ISystemStateTracker`.
- Follows the standard osquery event subscriber pattern — `init()` + `eventCallback()` handle the subscription lifecycle.
- `generateRow` / `generateRowList` are static, making them independently testable without a live subscriber instance.
