Windows-only header defining data structures, types, and interfaces for asynchronously reading NTFS USN (Update Sequence Number) Journal change records and dispatching them to osquery's file change event publisher.

## Key Components

### Structs

- **`USNFileReferenceNumber`** — Uniquely identifies a file within a volume; supports assignment from `DWORDLONG`, `FILE_ID_128`, and `GUID` Windows types, plus hashing via `std::hash` specialization using Boost.
- **`USNJournalEventRecord`** — Represents a single filesystem change event, including a `Type` enum (32 event types covering creates, deletes, renames, writes, attribute changes, etc.), timestamps, file name, and parent/node reference numbers.
- **`USNJournalReaderContext`** — Thread-safe shared state between the reader service and `FileChangePublisher`; holds the processed record list, a mutex, and a condition variable for wake-up signaling.

### Class

- **`USNJournalReader`** — An `InternalRunnable` (osquery dispatcher thread) that polls the Windows USN Journal, decompresses multi-reason records into discrete events, and dispatches them to the publisher via the shared context.

### Key Static Methods

- **`USNJournalReader::DecompressRecord`** — Expands a single USN record with multiple reason bits into individual `USNJournalEventRecord` entries, with deduplication via `USNPerFileLastRecordType`.
- **`USNJournalReader::ProcessAndAppendUSNRecord`** — Parses a raw `USN_RECORD*` and appends typed records to the output list.

### Namespace `USNParsers`

Low-level helpers that extract individual fields (`USN`, reference numbers, timestamps, attributes, reason bits, file names) from raw `USN_RECORD*` pointers, supporting both v2 (`DWORDLONG`) and v3 (`FILE_ID_128`) record formats.

## Usage Example

```c
// Construct a shared context for a drive and start the reader thread
auto ctx = std::make_shared<osquery::USNJournalReaderContext>();
ctx->drive_letter = 'C';

auto reader = std::make_shared<osquery::USNJournalReader>(ctx);
Dispatcher::addService(reader);

// Publisher side: wait for records and consume them
{
    WriteLock lock(ctx->processed_records_mutex);
    ctx->processed_records_cv.wait(lock);
    for (const auto& record : ctx->processed_record_list) {
        std::cout << record << "\n"; // uses operator<< overload
    }
    ctx->processed_record_list.clear();
}

// Signal shutdown
ctx->terminate = true;
```
