Brief description of the file's purpose: Declares `EtwPostProcessorsRunnable`, a runnable thread class that manages post-processing callbacks for ETW (Event Tracing for Windows) events, dispatching them to osquery event subscribers.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `EtwPostProcessorsRunnable` | Class | Thread-based runnable that consumes ETW events from a shared concurrent queue and dispatches them via registered post-processor callbacks |
| `addProvider()` | Method | Registers an `EtwProviderConfig` and its associated post-processor callback for one or more ETW event types |
| `CommonPostProcessing()` | Private Method | Applies common enrichment logic to every ETW event before provider-specific handling |
| `ProviderProcessors` | Type alias | `std::map<EtwEventType, EtwProviderConfig::EventProviderPostProcessor>` mapping event types to their handlers |
| `etwPostProcessors_` | Member | Stores all registered post-processor callbacks keyed by `EtwEventType` |
| `concurrentQueue_` | Member | Reference to the shared `ConcurrentEventQueueRef` that feeds incoming ETW events |
| `shouldRun_` | Member | Atomic boolean controlling the thread's run loop lifecycle |

## Usage Example

```cpp
#include <osquery/events/windows/etw/etw_post_processing_pipeline.h>
#include <osquery/events/windows/etw/etw_concurrent_queue.h>

// Create or obtain a shared concurrent queue
ConcurrentEventQueueRef sharedQueue = std::make_shared<ConcurrentEventQueue>();

// Instantiate the post-processing runnable
auto pipeline = std::make_shared<EtwPostProcessorsRunnable>(
    "EtwPostProcessorThread", sharedQueue);

// Register a provider config with its post-processor callback
EtwProviderConfig providerConfig;
// ... configure providerConfig with event types and callback ...

Status status = pipeline->addProvider(providerConfig);
if (!status.ok()) {
    LOG(ERROR) << "Failed to register provider: " << status.getMessage();
}

// Start the background thread via osquery's dispatcher
Dispatcher::addService(pipeline);
```

> **Note:** `EtwPostProcessorsRunnable` is `final` and extends `InternalRunnable`, integrating with osquery's `Dispatcher` infrastructure. The `start()`/`stop()` lifecycle is managed by the dispatcher — do not call them directly.
