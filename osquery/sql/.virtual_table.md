Defines the core virtual table interface for osquery's SQLite integration, providing data structures and functions that bridge osquery table plugins with SQLite's virtual table module.

## Key Components

### Structs

- **`BaseCursor`** — Represents a SQLite virtual table cursor. Tracks row position, result data (`TableRows`), an optional coroutine-based `RowGenerator`, and the current row holder during query execution.
- **`VirtualTable`** — Wraps the SQLite `sqlite3_vtab` structure, adding osquery-specific metadata (`VirtualTableContent`) and a reference to the thread-local `SQLiteDBInstance`.

### Globals

- **`kAttachMutex`** — A `RecursiveMutex` that serializes concurrent table attach operations, guarding non-thread-safe SQLite resources during schema registration and filter routing.

### Functions

| Function | Description |
|---|---|
| `attachTableInternal` | Attaches a named table plugin to a given SQLite DB instance |
| `detachTableInternal` | Drops (detaches) a named table from a SQLite DB instance |
| `attachFunctionInternal` | Registers a custom scalar function with SQLite |
| `attachVirtualTables` | Attaches all registered table plugins to an in-memory SQLite DB |
| `registerForeignTables` | Registers foreign/cross-platform table schema plugins (non-extension builds only) |

## Usage Example

```c
// Attach all virtual tables to a new SQLite DB instance
SQLiteDBInstanceRef instance = SQLiteDBManager::get();
attachVirtualTables(instance);

// Attach a single table by name
Status s = attachTableInternal("processes", instance, false);
if (!s.ok()) {
  LOG(ERROR) << "Failed to attach table: " << s.getMessage();
}

// Detach when done
detachTableInternal("processes", instance);
```

## Notes

- Both `BaseCursor` and `VirtualTable` inherit from `boost::noncopyable`, preventing accidental copies of SQLite-managed resources.
- `registerForeignTables()` is excluded from extension builds via the `OSQUERY_EXTERNAL` preprocessor guard.
