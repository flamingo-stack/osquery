Utility header providing RAII-based SQLite database lifecycle management, security authorization, and query planning for osquery's virtual table SQL layer.

## Key Components

### Constants
- **`SQLITE_SOFT_HEAP_LIMIT`** — 5MB soft heap cap for SQLite memory usage
- **`kAllowedSQLiteActionCodes`** — Allowlist of permitted SQLite action codes (blocks `SQLITE_ATTACH` to prevent arbitrary file writes)
- **`kAllowedSQLitePragmas`** — Allowlist of permitted SQLite pragma statements
- **`kSQLOpcodes`** — Map of SQLite opcodes used for column type inference

### Functions
- **`sqliteAuthorizer()`** — SQLite authorizer callback; enforces `kAllowedSQLiteActionCodes` and `kAllowedSQLitePragmas`
- **`queryInternal()`** — Executes a raw SQL query against a specific `SQLiteDBInstance`

### Classes

| Class | Purpose |
|---|---|
| `SQLiteDBInstance` | RAII wrapper around `sqlite3*`; manages primary or transient connections, cache state, and virtual table lifecycle |
| `SQLiteDBManager` | Singleton resource manager; sole entry point for obtaining SQLite connections |
| `QueryPlanner` | Lightweight query planner using SQLite `EXPLAIN` output to infer column types |

## Usage Example

```c
// Obtain a managed database connection
SQLiteDBInstanceRef db = SQLiteDBManager::get();

// Execute a query against it
QueryDataTyped results;
Status s = queryInternal("SELECT * FROM processes", results, db);
if (!s.ok()) {
    // handle error
}

// Run the query planner to infer column types
QueryPlanner planner("SELECT pid, name FROM processes", db);
TableColumns columns;
planner.applyTypes(columns);

// Tables touched by the query
for (const auto& table : planner.tables()) {
    // table is a std::string table name
}
```

> **Note:** Always use `SQLiteDBManager::get()` to access SQLite resources. Direct instantiation of `SQLiteDBInstance` is reserved for internal use. See the [source file](https://github.com/flamingo-stack/osquery/blob/main/osquery/sql/sqlite_util.h) for full API details.
