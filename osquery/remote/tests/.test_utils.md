Provides a singleton test utility class for managing a local TLS server process during osquery integration tests, along with helpers for configuring and restoring TLS-related client flags.

## Key Components

### `TLSServerRunner` (class)
A non-copyable singleton that spawns and manages a Python/script-based TLS server for testing osquery's TLS client functionality.

| Member | Description |
|--------|-------------|
| `instance()` | Returns the singleton instance |
| `start(server_cert, verify_client_cert)` | Starts the TLS server process; returns `false` on failure |
| `stop()` | Terminates the server process on exit |
| `port()` | Returns the TCP port string the server is bound to |
| `setClientConfig()` | Applies osquery flags needed for TLS client tests |
| `unsetClientConfig()` | Restores original flag values after tests |
| `getListeningPortPid(port, pid)` | Resolves the PID bound to a given port; empty on failure |
| `startAndSetScript(port, cert, verify)` | Internal helper to launch the server script and set `server_` handle |

**Private state:** `server_` (`PlatformProcess`), `port_`, `tls_hostname_`, `enroll_tls_endpoint_`, `tls_server_certs_`, `enroll_secret_path_`

## Usage Example

```cpp
#include "test_utils.h"

// In a test fixture SetUp:
bool started = osquery::TLSServerRunner::start("/path/to/server.crt", false);
ASSERT_TRUE(started);

osquery::TLSServerRunner::setClientConfig();

// Run TLS-dependent test logic...
std::string port = osquery::TLSServerRunner::port(); // e.g., "8080"

// Teardown:
osquery::TLSServerRunner::unsetClientConfig();
osquery::TLSServerRunner::stop();
```

> **Note:** `start()` is idempotent — calling it multiple times will not spawn duplicate server processes, making it safe to invoke from multiple test cases within the same process.
