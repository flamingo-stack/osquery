HTTP client interface for osquery's remote communication layer, providing HTTP/HTTPS request functionality built on Boost.Beast and OpenSSL.

## Key Components

### `Client`
Main HTTP client class supporting GET, POST, PUT, HEAD, and DELETE methods over plain or TLS-encrypted connections.

### `Client::Options`
Fluent builder for configuring client behavior. Supports chainable setters for:
- **TLS/SSL** — `ssl_connection()`, `openssl_ciphers()`, `openssl_options()`, `openssl_certificate()`, `openssl_private_key_file()`, `always_verify_peer()`
- **Connection** — `timeout()`, `keep_alive()`, `follow_redirects()`, `proxy_hostname()`, `remote_hostname()`, `remote_port()`

### `HTTP_Request<T>` / `HTTP_Response<T>`
Template wrappers around Boost.Beast request/response types, extending them with URI parsing helpers:
- `remoteHost()` — extracts hostname
- `remotePort()` — extracts port
- `remotePath()` — builds path + query + fragment
- `protocol()` — returns scheme (`http` / `https`)

### Type Aliases
```c
typedef HTTP_Request<beast_http_request>  Request;
typedef HTTP_Response<beast_http_response> Response;
```

### Constants
```c
const std::string kInstanceMetadataAuthority = "169.254.169.254"; // EC2/Azure metadata
```

## Usage Example

```cpp
#include <osquery/remote/http_client.h>

osquery::http::Client::Options opts;
opts.ssl_connection(true)
    .timeout(10)
    .always_verify_peer(true)
    .openssl_certificate("/etc/ssl/ca-bundle.crt");

osquery::http::Client client(opts);

osquery::http::Request req("https://example.com/api/data");
auto response = client.get(req);

// POST with body
osquery::http::Request post_req("https://example.com/api/submit");
auto response = client.post(post_req, "{\"key\":\"value\"}", "application/json");
```

> **Note:** SSL2, SSL3, MD5, and deprecated OpenSSL APIs are explicitly disabled via preprocessor macros. On Windows, Boost ASIO thread cleanup is handled via `std::call_once` to prevent socket lifecycle issues.
