Dispatcher service thread that implements osquery's query scheduler, executing scheduled queries at configurable intervals with time drift compensation.

## Key Components

### `SchedulerRunner` (class)
Extends `InternalRunnable` to run as a managed Dispatcher thread.

| Member | Description |
|--------|-------------|
| `SchedulerRunner(timeout, interval, max_time_drift)` | Constructor; configures run duration, step interval, and optional drift ceiling |
| `start()` | Thread entry point; executes the scheduling loop |
| `stop()` | Interrupt/shutdown hook |
| `getCurrentTimeDrift()` | Returns accumulated time drift in milliseconds |
| `calculateTimeDriftAndMaybePause(...)` | Adjusts sleep duration to compensate for loop overruns |
| `maybeRunDecorators(time_step)` | Fires interval-based query decorators |
| `maybeReloadSchedule(time_step)` | Reloads configuration schedule flags |
| `maybeFlushLogs(time_step)` | Flushes buffered status logs |
| `maybeScheduleCarves(time_step)` | Enqueues pending file carve requests |

### Free Functions

| Function | Description |
|----------|-------------|
| `monitor(name, query)` | Executes a single `ScheduledQuery` and returns results as `SQLInternal` |
| `startScheduler()` | Launches the scheduler with production config settings |
| `startScheduler(timeout, interval)` | Overload for testing with explicit timeout and step interval |

## Usage Example

```cpp
#include <osquery/scheduler/scheduler.h>

// Production startup (reads timeout/interval from config flags)
osquery::startScheduler();

// Test startup with explicit 60-second timeout, 5-second interval
osquery::startScheduler(60UL, 5);

// Manual runner construction with drift compensation capped at 500ms
osquery::SchedulerRunner runner(
    300UL,
    10,
    std::chrono::milliseconds{500}
);
runner.start();
```

## Notes

- `request_shutdown_on_expiration` defaults to `true` but is overridable in tests via `FRIEND_TEST`
- Time drift accumulates when loop steps exceed the configured `interval_` and is compensated by shortening subsequent sleep periods, up to `max_time_drift_`
