Shared test base class and macro utilities for validating osquery database plugin implementations against a common set of behavioral tests.

## Key Components

### `CREATE_DATABASE_TESTS(n)` Macro
Expands into a full suite of Google Test `TEST_F` cases for a given fixture class `n`. Registers the following test cases automatically:

| Test Case | Method |
|---|---|
| `test_plugin_check` | `testPluginCheck()` |
| `test_reset` | `testReset()` |
| `test_put` | `testPut()` |
| `test_putBatch` | `testPutBatch()` |
| `test_get` | `testGet()` |
| `test_delete` | `testDelete()` |
| `test_delete_range` | `testDeleteRange()` |
| `test_scan` | `testScan()` |
| `test_scan_limit` | `testScanLimit()` |

### `DatabasePluginTests` (abstract class)
A Google Test fixture base class in the `osquery` namespace. Subclasses must implement the pure virtual `name()` method to identify the plugin under test. Handles `SetUp`/`TearDown` lifecycle including database path management and plugin initialization.

**Protected members:**
- `path_` — path to the test database
- `previous_path_` — database path active before test setup

## Usage Example

```cpp
// Define a fixture for a specific database plugin (e.g., RocksDB)
class RocksDBDatabasePluginTests : public DatabasePluginTests {
 protected:
  std::string name() override {
    return "rocksdb";
  }
};

// Expand all standard database tests for this fixture
CREATE_DATABASE_TESTS(RocksDBDatabasePluginTests);
```

This pattern ensures every database plugin is validated against the same behavioral contract with minimal boilerplate. See the full source at [`https://github.com/flamingo-stack/osquery`](https://github.com/flamingo-stack/osquery).
