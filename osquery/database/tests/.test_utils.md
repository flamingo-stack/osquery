Shared test infrastructure for osquery database plugin unit tests, providing a reusable base fixture class and macro-driven test registration for validating `DatabasePlugin` implementations.

## Key Components

### `CREATE_DATABASE_TESTS(n)` Macro
Registers a standard suite of 9 Google Test cases against a given fixture class `n`, covering:
- `test_plugin_check` — validates plugin initialization
- `test_reset` — verifies reset behavior
- `test_put` / `test_putBatch` — single and batch write operations
- `test_get` — key lookup
- `test_delete` / `test_delete_range` — single and range deletion
- `test_scan` / `test_scan_limit` — full and limited key scanning

### `DatabasePluginTests` (class)
Abstract Google Test fixture (`testing::Test`) that manages plugin lifecycle across tests.

| Member | Type | Purpose |
|---|---|---|
| `path_` | `std::string` | Path to the temporary test database |
| `previous_path_` | `std::string` | Saved database path before `SetUp` |
| `name()` | pure virtual | Subclass must return the plugin name |
| `SetUp()` / `TearDown()` | override | Initializes and cleans up the plugin under test |
| `plugin_` | `shared_ptr<DatabasePlugin>` | Plugin instance ready for test execution |

## Usage Example

```cpp
// Declare a concrete fixture for a specific database plugin
class RocksDBPluginTests : public DatabasePluginTests {
 protected:
  std::string name() override {
    return "rocksdb";
  }
};

// Expand all standard database tests for this fixture
CREATE_DATABASE_TESTS(RocksDBPluginTests);
```

The macro expands into individual `TEST_F` definitions, so each test appears separately in GTest output with a descriptive name (e.g., `RocksDBPluginTests.test_put`).
