RAII wrapper around a Windows `HANDLE` for safely managing the lifecycle of Windows kernel objects such as object directories and symbolic links.

## Key Components

### `Handle` Class

A scoped handle manager within the `osquery` namespace that wraps a raw Win32 `HANDLE`, providing clean open/close semantics and status-based error reporting.

| Method | Description |
|--------|-------------|
| `Handle()` / `~Handle()` | Constructor initializes an invalid handle; destructor closes it automatically |
| `openDirObj(const std::wstring&)` | Opens a Windows object directory with `OPEN_DIRECTORY` access mask |
| `openSymLinkObj(const std::wstring&)` | Opens a Windows symbolic link with `SYMBOLIC_LINK_QUERY` access mask |
| `getAsHandle()` | Returns the underlying raw `HANDLE` |
| `close()` | Explicitly closes the handle |
| `valid()` | Returns `true` if the handle is currently open and valid |

## Usage Example

```cpp
#include <osquery/utils/system/handle.h>

osquery::Handle h;

// Open a Windows object directory (e.g., "\BaseNamedObjects")
auto status = h.openDirObj(L"\\BaseNamedObjects");
if (!status.ok()) {
  LOG(ERROR) << "Failed to open directory: " << status.getMessage();
  return;
}

// Use the raw handle if needed by a Win32 API
HANDLE raw = h.getAsHandle();

// Explicit close (also called automatically on destruction)
h.close();
```

> **Note:** This file is Windows-specific and depends on `osquery/utils/system/system.h`. It should only be compiled on Windows targets.
