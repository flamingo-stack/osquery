Defines column metadata types used throughout osquery's table plugin system, providing the building blocks for describing table schema, query optimization hints, and column behavior.

## Key Components

### `ColumnOptions` (enum class)
Bitmask flags controlling column behavior:

| Flag | Value | Purpose |
|------|-------|---------|
| `DEFAULT` | 0 | No special behavior |
| `INDEX` | 1 | Treat as primary key |
| `REQUIRED` | 2 | Must appear in query predicate |
| `ADDITIONAL` | 4 | Unlocks additional result context when in predicate |
| `OPTIMIZED` | 8 | Enables query path optimization when in predicate |
| `HIDDEN` | 16 | Excluded from `SELECT *` results |
| `COLLATEBINARY/NOCASE/RTRIM/VERSION*` | 32–2048 | Custom SQLite collation sequences |

**Operators:** `|` and `&` are overloaded to support bitmask composition.

### `ColumnType` (enum)
SQLite-compatible column data types: `TEXT_TYPE`, `INTEGER_TYPE`, `BIGINT_TYPE`, `UNSIGNED_BIGINT_TYPE`, `DOUBLE_TYPE`, `BLOB_TYPE`, `UNKNOWN_TYPE`.

### Type Aliases
- **`TableName`** — `std::string` alias for table plugin names
- **`TableColumns`** — Ordered vector of `(name, ColumnType, ColumnOptions)` tuples describing a table's schema
- **`ColumnAliasSet`** — Map of column names to their alias sets

### `kColumnTypeNames`
External map from `ColumnType` to its SQLite string representation (e.g., `TEXT_TYPE` → `"TEXT"`).

## Usage Example

```c
#include <osquery/core/tables.h>
#include "column.h"

using namespace osquery;

// Define schema for a table plugin
TableColumns MyTable::columns() const {
  return {
    {"uid",      BIGINT_TYPE,  ColumnOptions::INDEX},
    {"username", TEXT_TYPE,    ColumnOptions::DEFAULT},
    {"domain",   TEXT_TYPE,    ColumnOptions::OPTIMIZED | ColumnOptions::HIDDEN},
  };
}
```
