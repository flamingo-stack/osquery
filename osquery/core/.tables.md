Defines the core data structures and type system for osquery's virtual table interface, bridging SQLite query constraints with table plugin implementations.

## Key Components

### Type Affinity Macros
- `SQL_TEXT(x)`, `INTEGER(x)`, `BIGINT(x)`, `UNSIGNED_BIGINT(x)`, `DOUBLE(x)` — Convert native C++ values to SQLite-compatible string representations via `__sqliteField()`
- `TEXT_LITERAL`, `INTEGER_LITERAL`, `BIGINT_LITERAL`, `UNSIGNED_BIGINT_LITERAL`, `DOUBLE_LITERAL` — C++ type aliases for SQLite affinities
- `SQL_NULL_RESULT` — Defines NULL as an empty string `""`

### Enumerations
- `ConstraintOperator` — SQL predicate operators (`EQUALS`, `GREATER_THAN`, `LIKE`, `GLOB`, `REGEXP`, `IN_OP`, etc.)
- `TableAttributes` — Bitfield flags describing table behavior (`CACHEABLE`, `EVENT_BASED`, `USER_BASED`, `UTILITY`, `PENDING`)

### Structs
- `Constraint` — Pairs an operator with an expression string for a single predicate
- `ConstraintList` — Collection of `Constraint`s for a single column; provides `matches()`, `exists()`, `existsAndMatches()`, `notExistsOrMatches()`, and `getAll()` helpers

### Type Aliases
- `TableColumns` — Ordered vector of `(name, ColumnType, ColumnOptions)` tuples
- `ConstraintMap` — Maps column names to their `ConstraintList`
- `ConstraintSet` — Vector of `(column, Constraint)` pairs from parsed predicates
- `UsedColumns` / `UsedColumnsBitset` — Track which columns are referenced in a query

## Usage Example

```cpp
// Check if a constraint on "uid" equals a specific value
ConstraintMap constraints;
if (constraints.count("uid")) {
  const auto& list = constraints.at("uid");

  // Get all EQUALS expressions for uid
  auto uids = list.getAll(ConstraintOperator::EQUALS);
  for (const auto& uid : uids) {
    // Filter results by uid
  }

  // Or check a specific value
  if (list.notExistsOrMatches("1000")) {
    // Include this row
  }
}

// Build a row using type macros
Row r;
r["uid"]  = BIGINT(1000);
r["name"] = SQL_TEXT("alice");
r["gid"]  = INTEGER(100);
```
