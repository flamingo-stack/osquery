Defines the abstract `SQLPlugin` interface for osquery's pluggable SQL backend, allowing the SQL implementation (e.g., SQLite) to be registered and swapped via the osquery plugin registry without coupling core SDK code to third-party dependencies.

## Key Components

- **`SQLPlugin`** — Abstract plugin class inheriting from `Plugin` that defines the contract for SQL backend implementations:
  - `query()` — Executes a SQL query string, returning results in a `QueryData` object
  - `getQueryColumns()` — Parses a query and returns column metadata (`name`, `type`) as `TableColumns`
  - `getQueryTables()` — Extracts the list of scanned table names from a query
  - `attach()` — Virtual hook to attach a named virtual table at runtime (default: no-op success)
  - `detach()` — Virtual hook to detach a named virtual table (default: no-op success)
  - `call()` — Overrides the base `Plugin::call()` to handle `PluginRequest`/`PluginResponse` dispatch

## Usage Example

```cpp
#include <osquery/sql/sql.h>

class MySQLPlugin : public osquery::SQLPlugin {
 public:
  osquery::Status query(const std::string& q,
                        osquery::QueryData& results,
                        bool use_cache) const override {
    // Execute query against custom SQL backend
    return osquery::Status::success();
  }

  osquery::Status getQueryColumns(const std::string& q,
                                  osquery::TableColumns& cols) const override {
    // Parse and return column metadata
    return osquery::Status::success();
  }

  osquery::Status getQueryTables(const std::string& q,
                                 std::vector<std::string>& tables) const override {
    // Extract referenced table names
    return osquery::Status::success();
  }
};

REGISTER(MySQLPlugin, "sql", "sql");
```
