Defines the abstract `SQLPlugin` interface that backs osquery's pluggable SQL execution layer, allowing the SQL implementation (e.g., SQLite) to be swapped via the osquery registry without coupling the SDK to third-party dependencies.

## Key Components

### `SQLPlugin` (abstract class)
Extends `Plugin` and declares the contract every SQL backend must fulfill:

| Method | Description |
|--------|-------------|
| `query()` | Execute a SQL query string; results returned via `QueryData` |
| `getQueryColumns()` | Parse a query and return column metadata (`TableColumns`) |
| `getQueryTables()` | Return the list of tables scanned by a query |
| `attach()` | Attach a virtual table at runtime (default: no-op success) |
| `detach()` | Detach a virtual table by name (default: no-op success) |
| `call()` | Registry dispatch entry point (overrides `Plugin::call`) |

## Usage Example

```cpp
#include <osquery/sql/sql.h>

class MySQLPlugin : public osquery::SQLPlugin {
 public:
  osquery::Status query(const std::string& q,
                        osquery::QueryData& results,
                        bool use_cache) const override {
    // Execute query against your SQL backend
    return osquery::Status::success();
  }

  osquery::Status getQueryColumns(const std::string& q,
                                  osquery::TableColumns& cols) const override {
    // Inspect and return column metadata
    return osquery::Status::success();
  }

  osquery::Status getQueryTables(const std::string& q,
                                 std::vector<std::string>& tables) const override {
    // Return referenced table names
    return osquery::Status::success();
  }
};

REGISTER(MySQLPlugin, "sql", "sql");
```

## Notes

- The registry key for this plugin type is `"sql"`, and exactly one registration named `"sql"` is expected at runtime.
- The default `libosquery_additional` build wires in SQLite as the concrete implementation.
