Declares the shutdown coordination interface for the osquery daemon, providing functions to request, monitor, and wait on graceful application termination across threads and signal handlers.

## Key Components

| Function | Description |
|----------|-------------|
| `requestShutdown(int, string)` | Primary shutdown trigger; signals all services to stop. Accepts optional system log message for failure cases. |
| `waitForShutdown()` | Blocks the calling thread until shutdown is requested. Intended to be called before `Initializer::shutdown`. |
| `waitTimeoutOrShutdown(milliseconds)` | Interruptible sleep; returns early if shutdown is requested. Useful during retry loops. |
| `shutdownRequested()` | Non-blocking check for shutdown state. Primarily for non-daemon tools like the shell. |
| `getShutdownExitCode()` | Returns the exit code set by the shutdown requester. |
| `setShutdownExitCode(int)` | Directly sets the exit code without triggering shutdown flow. |
| `resetShutdown()` | Resets shutdown state; intended for internal use and testing only. |

## Usage Example

```cpp
#include <osquery/core/shutdown.h>

// In your main thread — block until shutdown is signaled
waitForShutdown();
int code = getShutdownExitCode();

// In a retry loop — sleep up to 30s but exit early on shutdown
bool shutdownOccurred = waitTimeoutOrShutdown(std::chrono::milliseconds(30000));
if (shutdownOccurred) {
  return;
}

// Trigger shutdown with a system log message on unrecoverable error
requestShutdown(EXIT_FAILURE, "Database connection permanently lost");
```

## Notes

- `requestShutdown` is safe to call from signal handlers and service stop events.
- Prefer `requestShutdown` over `setShutdownExitCode` in application code.
- `resetShutdown` should not be used in production paths — testing only.
