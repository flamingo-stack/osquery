Defines the plugin interface for the osquery numeric monitoring system, providing an abstract base class that monitoring backend plugins must implement.

## Key Components

- **`NumericMonitoringPlugin`** — Abstract plugin class inheriting from `Plugin` that serves as the interface for numeric monitoring backends (e.g., filesystem-based monitoring). Overrides `call()` to handle plugin dispatch via `PluginRequest`/`PluginResponse`.

## Usage Example

```c
// Implement a custom numeric monitoring backend
class MyMonitoringPlugin : public NumericMonitoringPlugin {
 public:
  Status call(const PluginRequest& request,
              PluginResponse& response) override {
    // Extract monitoring point and value from request
    // Write to your custom backend (e.g., remote metrics store)
    return Status::success();
  }
};

// Register the plugin with osquery's registry
REGISTER(MyMonitoringPlugin, "numeric_monitoring", "my_backend");
```

The built-in reference implementation is `NumericMonitoringFilesystemPlugin` ([`osquery/numeric_monitoring/plugins/filesystem.h`](https://github.com/flamingo-stack/osquery/blob/main/osquery/numeric_monitoring/plugins/filesystem.h)).

## Notes

- Plugins communicate via the standard `PluginRequest` / `PluginResponse` map-based interface inherited from `Plugin`.
- The monitoring value types and pre-aggregation semantics are defined in [`osquery/numeric_monitoring/numeric_monitoring.h`](https://github.com/flamingo-stack/osquery/blob/main/osquery/numeric_monitoring/numeric_monitoring.h).
- Part of the broader osquery plugin registry pattern — register implementations using the `"numeric_monitoring"` registry name.
