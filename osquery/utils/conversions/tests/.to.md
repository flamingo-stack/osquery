Unit tests for the `to<>` conversion utility in osquery, specifically validating string conversion behavior for scoped (`enum class`) enumerations.

## Key Components

- **`NonFailingConversionsTests`** — GTest fixture class grouping conversion tests that are expected to succeed without errors.
- **`TestGreenColor`** / **`TestOrangeColor`** — Local `enum class` types used as test subjects to verify generic enum-to-string conversion.
- **`to_string_from_enum_class`** — Verifies that `to<std::string>()` produces a human-readable representation (e.g., `"TestGreenColor[0]"`) for scoped enum values.
- **`to_string_from_old_enum`** — Verifies the same behavior for a second enum type, covering all four enumerators including index-based formatting.

## Usage Example

```cpp
#include <osquery/utils/conversions/to.h>

enum class TestGreenColor {
  Green,  // index 0
  Pine,   // index 1
  Fern,   // index 2
};

// Converts enum value to a string containing "TestGreenColor[N]"
std::string result = to<std::string>(TestGreenColor::Pine);
// result contains: "TestGreenColor[1]"
```

## Notes

- The `to<std::string>()` template produces output in the format `TypeName[index]`, where the index corresponds to the enum's underlying integer value.
- Tests use `find() != npos` rather than exact equality, allowing the implementation to include additional context around the formatted enum string.
- Both test cases confirm that the conversion is zero-indexed and consistent across different enum types.
