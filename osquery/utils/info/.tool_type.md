Defines the `ToolType` enumeration and related utilities for identifying the runtime mode of an osquery process (daemon, shell, extension, etc.).

## Key Components

### Enum: `ToolType`

| Value | Description |
|-------|-------------|
| `UNKNOWN` | Default/undetected type |
| `SHELL` | Interactive osquery shell (`osqueryi`) |
| `DAEMON` | Background osquery daemon (`osqueryd`) |
| `TEST` | Unit test runner context |
| `EXTENSION` | osquery extension process |
| `SHELL_DAEMON` | Combined shell/daemon mode |

### Functions

- **`setToolType(ToolType tool)`** — Sets the global tool type at process startup, typically called by the `Initializer` class.
- **`getToolType()`** — Returns the currently set `ToolType` for runtime branching decisions.
- **`isDaemon()`** — Convenience check; returns `true` if the current tool type is `DAEMON`.
- **`isShell()`** — Convenience check; returns `true` if the current tool type is `SHELL`.

## Usage Example

```c
#include <osquery/core/tool_type.h>

// At startup (typically within Initializer)
osquery::setToolType(osquery::ToolType::DAEMON);

// Later, in runtime logic
if (osquery::isDaemon()) {
  // Daemon-specific behavior
}

if (osquery::getToolType() == osquery::ToolType::EXTENSION) {
  // Extension-specific behavior
}
```

## Notes

- The `ToolType` is detected and set by the `Initializer` class using the binary name and compile-time flags.
- Used throughout osquery to gate behavior that should only run in specific process modes (e.g., logging verbosity, config loading, scheduler activation).
