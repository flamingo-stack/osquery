SQLite-backed implementation of osquery's `DatabasePlugin` interface, providing persistent key-value storage for osquery's internal/core data using an embedded SQLite3 database.

## Key Components

### `SQLiteDatabasePlugin`
Concrete class extending `DatabasePlugin` with full CRUD and lifecycle management:

| Method | Description |
|--------|-------------|
| `get()` | Retrieve `string` or `int` value by domain + key |
| `put()` | Store `string` or `int` value by domain + key |
| `putBatch()` | Bulk-insert a list of string key-value pairs |
| `remove()` | Delete a single key from a domain |
| `removeRange()` | Delete all keys within a lexicographic range |
| `scan()` | List keys in a domain, with optional prefix filter and result cap |
| `setUp()` | Opens/initializes the SQLite database file |
| `tearDown()` / `~SQLiteDatabasePlugin()` | Closes and cleans up the database handle |

### Private Members
- `sqlite3* db_` — Raw SQLite3 database handle (initialized to `nullptr`)
- `Mutex close_mutex_` — Guards safe concurrent teardown

### Plugin Registration
```cpp
REGISTER_INTERNAL(SQLiteDatabasePlugin, "database", "sqlite");
```
Registers the plugin as the internal `sqlite` provider under the `database` category.

## Usage Example

```cpp
// Plugin is auto-registered; typical usage goes through the DatabasePlugin API:
auto db = RegistryFactory::get().plugin("database", "sqlite");

// Store a value
db->put("configs", "refresh_interval", "60");

// Retrieve a value
std::string value;
db->get("configs", "refresh_interval", value);

// Scan keys with prefix
std::vector<std::string> keys;
db->scan("configs", keys, "refresh_", 100);

// Remove a key
db->remove("configs", "refresh_interval");
```

> The database file path is controlled by the `--database_path` flag declared via `DECLARE_string(database_path)`.
