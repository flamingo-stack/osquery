SQLite-backed implementation of osquery's `DatabasePlugin` interface, providing persistent key-value storage using an embedded SQLite3 database.

## Key Components

- **`SQLiteDatabasePlugin`** — Concrete `DatabasePlugin` subclass registered as the internal `"sqlite"` database provider
  - `get()` — Retrieves string or integer values by domain/key
  - `put()` — Stores string or integer values by domain/key
  - `putBatch()` — Bulk-inserts a list of string key-value pairs into a domain
  - `remove()` — Deletes a single key from a domain
  - `removeRange()` — Deletes all keys within a lexicographic range in a domain
  - `scan()` — Lists keys in a domain, optionally filtered by prefix and capped by count
  - `setUp()` — Opens and initializes the SQLite database file
  - `tearDown()` / destructor — Safely closes the database via `close()`

- **`db_`** — Raw `sqlite3*` handle to the long-lived database connection
- **`close_mutex_`** — Mutex guarding concurrent access during teardown

## Usage Example

```c
// Plugin is auto-registered; interact via the DatabasePlugin interface:
auto db = RegistryFactory::get().plugin("database", "sqlite");

// Store a value
db->put("config", "refresh_interval", "60");

// Retrieve a value
std::string value;
db->get("config", "refresh_interval", value);

// Scan keys with a prefix
std::vector<std::string> keys;
db->scan("config", keys, "refresh_", 100);

// Remove a key
db->remove("config", "refresh_interval");
```

> The plugin is registered internally via `REGISTER_INTERNAL` and uses the path specified by the `--database_path` flag for its SQLite file.
