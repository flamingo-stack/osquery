RocksDB database plugin implementation header for osquery, defining the plugin class and internal logger that back the osquery database abstraction layer with a RocksDB storage engine.

## Key Components

### `GlogRocksDBLogger`
A custom `rocksdb::Logger` subclass that intercepts internal RocksDB log events (warnings, errors) and forwards them to Glog rather than losing them to stderr.

### `RocksDBDatabasePlugin`
Concrete implementation of `DatabasePlugin` using RocksDB as the storage backend. Manages column families as logical domains and exposes the full database interface:

| Method | Description |
|--------|-------------|
| `get()` | Retrieve string or integer values by domain/key |
| `put()` | Store string or integer values; `putBatch()` for bulk writes |
| `remove()` / `removeRange()` | Delete single keys or key ranges |
| `scan()` | Iterate keys in a domain with optional prefix filter and limit |
| `setUp()` / `tearDown()` | Lifecycle management — open/close the RocksDB instance |
| `compactFiles()` | Trigger per-domain compaction |
| `repairDB()` | Best-effort corruption recovery |
| `setCorrupted()` / `isCorrupted()` | Track and query global corruption state |

**Private members** include the raw `rocksdb::DB*` handle, column family handles/descriptors, connection options, the shared logger instance, and a `close_mutex_` for safe teardown.

## Usage Example

```c
// Registered and invoked through the osquery plugin system:
auto plugin = std::make_shared<RocksDBDatabasePlugin>();

Status s = plugin->setUp();
if (!s.ok()) {
    // handle setup failure or corruption
}

std::string value;
plugin->put("domain_name", "my_key", "my_value");
plugin->get("domain_name", "my_key", value); // value == "my_value"

std::vector<std::string> keys;
plugin->scan("domain_name", keys, /*prefix=*/"", /*max=*/100);

plugin->tearDown();
```
