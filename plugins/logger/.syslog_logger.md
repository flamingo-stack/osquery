Defines the `SyslogLoggerPlugin` class, an osquery logger plugin that forwards query results and status messages to the system syslog facility.

## Key Components

- **`SyslogLoggerPlugin`** — Extends `LoggerPlugin` to route osquery output through the POSIX `syslog` interface
  - `usesLogStatus()` — Returns `true`, enabling status log forwarding to syslog
  - `logString(const std::string& s)` — Writes a single log string entry to syslog
  - `init(const std::string& name, const std::vector<StatusLogLine>& log)` — Initializes the plugin and flushes any buffered startup logs
  - `logStatus(const std::vector<StatusLogLine>& log)` — Forwards a batch of status log lines to syslog

- **`REGISTER` macro** — Registers `SyslogLoggerPlugin` under the `"logger"` category with the name `"syslog"` in the osquery plugin registry

## Usage Example

Enable the syslog logger by setting the `--logger_plugin` flag at osquery startup:

```bash
osqueryd --logger_plugin=syslog
```

To use programmatically within an osquery plugin context:

```c
// The plugin is auto-registered via the REGISTER macro.
// To retrieve it from the registry at runtime:
auto plugin = Registry::getPlugin("logger", "syslog");

// Direct instantiation (typically handled by the registry):
SyslogLoggerPlugin logger;
logger.init("osqueryd", bufferedLogs);

Status result = logger.logString("{\"name\":\"processes\",\"action\":\"added\"}");
if (!result.ok()) {
  // handle error
}
```

Log output will appear in the system journal (e.g., `/var/log/syslog` or `journalctl`) under the osquery process name.
