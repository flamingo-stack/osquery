Defines the `SyslogLoggerPlugin` class, an osquery logger plugin that routes query results and status messages to the system syslog daemon.

## Key Components

- **`SyslogLoggerPlugin`** — Extends `LoggerPlugin` to implement syslog-based logging for osquery
- **`usesLogStatus()`** — Returns `true`, indicating this plugin handles status log lines
- **`logString()`** — Writes a single log string entry to syslog
- **`init()`** — Initializes the plugin with a name and any buffered status log lines
- **`logStatus()`** — Writes a batch of `StatusLogLine` entries to syslog
- **`REGISTER` macro** — Registers the plugin under the `"logger"` registry with the key `"syslog"`

## Usage Example

```c
// Enable the syslog logger via osquery configuration flag:
// --logger_plugin=syslog

// Or programmatically reference the registered plugin:
auto plugin = RegistryFactory::get().plugin("logger", "syslog");

// Once active, osquery routes results and status messages
// through SyslogLoggerPlugin::logString() and logStatus(),
// which write to the system syslog using <syslog.h> facilities.

// Example syslog output visible via:
// journalctl -t osqueryd
// or: tail -f /var/log/syslog | grep osquery
```

> **Note:** This plugin integrates directly with the host OS syslog daemon (e.g., `rsyslog`, `syslog-ng`, `journald`), making osquery logs available alongside other system services without requiring a separate log file.
