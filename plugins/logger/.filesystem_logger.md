Declares the `FilesystemLoggerPlugin` class, an osquery logger plugin that writes query results, snapshots, and status logs to the local filesystem.

## Key Components

**`FilesystemLoggerPlugin`** — Extends `LoggerPlugin` with filesystem-backed logging:

| Method | Description |
|--------|-------------|
| `setUp()` | Initializes the plugin and prepares log file handles |
| `logString()` | Writes differential query results to a dedicated log path |
| `logSnapshot()` | Writes snapshot query results to a separate log path |
| `logStatus()` | Forwards status/severity logs to Glog |
| `init()` | Post-startup initialization; uniquely may return an error to allow Glog direct file access |
| `logStringToFile()` *(private)* | Internal helper that handles the actual file write operation |

**`pimpl_`** — Private implementation pointer (`struct impl`) using the PImpl idiom to hide filesystem handle details and reduce compile-time dependencies.

**`REGISTER` macro** — Registers `FilesystemLoggerPlugin` under the `"logger"` registry with the key `"filesystem"`.

## Usage Example

The plugin is auto-registered and activated via osquery configuration:

```bash
osqueryd --logger_plugin=filesystem \
         --logger_path=/var/log/osquery \
         --logger_snapshot_event_type=true
```

To reference the plugin programmatically within an osquery extension:

```c
// Retrieve the active filesystem logger from the registry
auto plugin = Registry::getPlugin("logger", "filesystem");

// Log a custom JSON result string
plugin->call({{"string", "{\"action\":\"added\",\"name\":\"example\"}"}}, response);
```

## Notes

- Differential results and snapshots are written to **distinct file paths**, keeping event streams separate.
- The PImpl pattern (`struct impl`) encapsulates internal state, keeping the public header clean.
