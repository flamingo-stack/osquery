Implements a special-purpose config plugin that enables asynchronous configuration updates from plugins back to the osquery core process.

## Key Components

- **`UpdateConfigPlugin`** — A `ConfigPlugin` subclass registered under the `"config/update"` route. Acts as a relay endpoint for plugin-initiated config changes, routing update requests from extensions back to core.
- **`genConfig()`** — Stub implementation (returns `Status(0, "Unused")`); this plugin's role is routing, not config generation.
- **`REGISTER` macro** — Registers the plugin as `"update"` in the `"config"` registry category.

## Usage Example

Extension plugins that need to push config changes asynchronously should call `Config::update` directly rather than invoking this plugin explicitly:

```cpp
// Inside an extension plugin performing an async config update:
Config::get().update({{"my_plugin", R"({"queries": {...}})"}});

// osquery's Config::update internally checks if running as an extension.
// If external, it routes via the registry to "config/update" in core,
// which this plugin handles transparently.
```

> **Note:** Plugin authors do not need to implement call-chaining manually. The registry automatically forwards `"config/update"` requests from external (extension) processes to core when the route is missing locally — this plugin provides that missing route on the core side.
