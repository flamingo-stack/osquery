Provides the decorator system interface for osquery, enabling dynamic metadata attachment to log items at defined execution points (load, always, interval).

## Key Components

**`DecorationPoint` (enum)**
Defines when decorators execute:
- `DECORATE_LOAD` — runs once at config load
- `DECORATE_ALWAYS` — runs on every query cycle
- `DECORATE_INTERVAL` — runs on a timed interval

**`kDecorationPointKeys` (extern map)**
Maps each `DecorationPoint` enum value to its corresponding configuration key string.

**`runDecorators()`**
Iterates and executes all discovered decorators for a given decoration point. Accepts an optional timestamp for interval-based decorators and an optional source to restrict execution to a specific config source.

**`getDecorations()`**
Retrieves the current decoration result set as a `map<string, string>` of column name to value. Results are appended to log items before dispatch to downstream logging APIs (`logString`, `logSnapshot`, etc.).

**`clearDecorations()`**
Clears stored decoration results for a specific config source, typically called when that source updates.

## Usage Example

```cpp
#include <osquery/core/decorators.h>

// Run decorators that should always execute
osquery::runDecorators(osquery::DECORATE_ALWAYS);

// Run interval-based decorators with current epoch time
osquery::runDecorators(osquery::DECORATE_INTERVAL, getCurrentTime());

// Retrieve accumulated decorations and attach to a log record
std::map<std::string, std::string> decorations;
osquery::getDecorations(decorations);

for (const auto& kv : decorations) {
    logRecord[kv.first] = kv.second;
}

// Clear decorations when a config source refreshes
osquery::clearDecorations("filesystem");
```
