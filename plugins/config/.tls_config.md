Declares the `TLSConfigPlugin` class, which fetches osquery configuration over a TLS-secured HTTP connection from a remote config server.

## Key Components

### `TLSConfigPlugin`
Inherits from `ConfigPlugin` and `std::enable_shared_from_this<TLSConfigPlugin>`. Implements remote TLS-based configuration retrieval.

| Member | Type | Description |
|--------|------|-------------|
| `setUp()` | `Status` | Initializes the plugin; validates and caches the remote endpoint URL |
| `genConfig()` | `Status` | Fetches configuration data from the TLS endpoint and populates the config map |
| `uri_` | `std::string` (protected) | Cached remote endpoint URL, computed once during `setUp()` |

## Usage Example

```cpp
#include <osquery/config/plugins/tls_config.h>

// Typically registered and invoked by the osquery config subsystem.
// Direct usage via the plugin registry:
auto plugin = std::make_shared<osquery::TLSConfigPlugin>();

osquery::Status status = plugin->setUp();
if (!status.ok()) {
    LOG(ERROR) << "TLS config setup failed: " << status.getMessage();
}

std::map<std::string, std::string> config;
status = plugin->genConfig(config);
if (status.ok()) {
    for (const auto& [key, value] : config) {
        // Process retrieved config segments
    }
}
```

## Notes

- The plugin is registered with osquery's `ConfigPlugin` interface and is invoked automatically when `--config_plugin=tls` is set.
- `uri_` is populated during `setUp()` to avoid redundant URL resolution on each `genConfig()` call.
- `TLSConfigTests` is declared a `friend` class to allow white-box unit testing of internal state.
