Defines the `TLSConfigPlugin` class, which fetches osquery configuration from a remote TLS endpoint and integrates with the osquery config and dispatcher subsystems.

## Key Components

### `TLSConfigPlugin`
Inherits from `ConfigPlugin` and `std::enable_shared_from_this<TLSConfigPlugin>`. Responsible for retrieving configuration over a TLS-secured connection.

| Member | Type | Description |
|--------|------|-------------|
| `setUp()` | `Status` | Initializes the plugin, validates TLS endpoint settings |
| `genConfig()` | `Status` | Fetches and populates the configuration map from the remote TLS endpoint |
| `uri_` | `std::string` (protected) | Cached URL of the TLS config endpoint, computed once during setup |

## Usage Example

```cpp
#include <osquery/config/plugins/tls_config.h>

// Plugin is registered and managed by the osquery plugin system.
// Typical registration in a plugin entry point:

REGISTER(TLSConfigPlugin, "config", "tls");

// osquery internals will then call:
// plugin->setUp();
// plugin->genConfig(configMap);
```

The plugin is typically activated via the osquery `--config_plugin=tls` flag, pointing to a TLS-enabled configuration server endpoint.

## Notes

- `uri_` is computed and cached during `setUp()` to avoid redundant URL resolution on repeated `genConfig()` calls.
- `TLSConfigTests` is declared a `friend` class to allow unit test access to internals.
